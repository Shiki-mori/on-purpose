# 开发 On Purpose 扩展

遵守仓库根目录 `AGENTS.md`。本技能适用于该仓库的扩展开发，包括原有任务完成后的维护。

## 确定范围

1. 以用户当前请求确定本次行为与相关文件，读取对应实现及需求、设计章节。读取 [reference.md](reference.md) 定位共享接口和容易遗漏的约束。
2. 只有在请求“继续任务书／下一项”时，读取 `docs/assignment/assignment-book.md` 第 13 节选择最小未完成项，再读该项及第 3、4 节。第 13 节全部完成时，不根据旧总表或交接文档重新开始任务；用户仅说“继续”且没有可推断目标时，说明完成情况并澄清目标。
3. 原任务的“本项不做”及消息接入阶段只约束按任务书推进的场景。修复现有功能时可改必要的相关文件与已接入消息，不用为了旧阶段边界绕路。

## 实现

- 共享接口、常量、种子与文案复用现有定义；需求或设计发生有意变更时，同步修订对应文档及相关引用。
- 现有需求已明确而实现有缺陷时，修复实现。文档互相冲突时先核对最新功能条款与修订，不把旧数值写回代码；无法判定且会改变行为的差异交给用户选择。
- 保持页面通过消息请求、服务工作线程串行处理与持久化的边界。涉及记录写入、关闭标签页时检查失败分支；涉及状态机时检查其他标签页和正在进行的询问／打断／暂时关闭。
- 变更存储结构或播种时检查旧版本迁移和重复加载，不覆盖用户数据；修改显示排序时不要改写持久化 `order`。

## 验证与交付

- 按根目录指令完成改动文件的语法、清单与架构检查。只运行与改动有关的验证，不引入与本次改动无关的构建工具。
- 从当前需求验收项中选择受影响场景；任务书旧验收数值与最新功能冲突时，以最新条款为准并说明。例如默认间隔为 3 分钟，但明确把间隔设为 5 分钟的计时测试仍有效。
- 真实浏览器验证需确认已加载 `extension/` 的 Chrome 普通窗口。涉及多标签页、刷新、后台／休眠、重载、保存失败的改动，核对相应场景。无法实测时列出缺口，不声称完成全部验收。
- 仅当确实推进历史任务时维护第 13 节状态。后续修复或规则维护不重写历史完成日期，也不抹去未测备注。
- 最终说明改变的行为、验证结果和剩余限制。
