## 1. 用法

1. 从编号最小、状态为「未开始」的任务做起。一次只做一项。
2. 该项验收表里的每一行都在 Chrome 里对照过，再把第 13 节的状态改为「已完成」，然后才开始下一项。
3. 数据形状、消息 `type`、站点函数在任务 1 按系统设计建好。后面的任务只往上填行为。
4. 验收方式：在 `chrome://extensions` 打开开发者模式，加载仓库里的 `extension/`。改完代码后在该页重新加载。用普通窗口打开哔哩哔哩。无痕窗口默认没有这个扩展。
5. 需求或设计写错时，先改那份已确认文档并留下修订，再改代码。任务书不单独改已经确定的行为。
6. 环境当时做不到的验收（例如无法让电脑休眠）记在第 13 节备注里。除各任务另行写明的以外，缺行就不能标成已完成。

编码约束同时放在 Cursor 会读取的项目规范里。`.cursor/rules/` 在对话里生效。`.cursor/skills/implement-extension-task/` 写明做当前任务的步骤和共享约定。`.cursor/hooks.json` 会拦住扩展里的 ES Module、弹出页或内容脚本直接读写存储、扩展发起网络请求，以及引入打包工具。任务范围和验收仍以本文为准。

需求第 7 节的四步与本文任务的对应：

| 需求步骤 | 本文任务 | 为什么再拆 |
| --- | --- | --- |
| 1 目的询问、记录、复盘 | 任务 1、2、3 | 先让扩展和数据能加载，再走通主页，最后补全触发范围 |
| 2 共用计时与时长打断 | 任务 4、5 | 先让间隔和打断选项能改，再接计时和每个标签页上的窗口 |
| 3 暂时关闭 | 任务 6 | 单独一步 |
| 4 站点配置与流程分开 | 任务 7 | 核对前六项是否已经只通过站点模块认网址 |

## 3. 全程都要遵守

这些约束对每一项都有效。

- 清单版本为 Manifest V3。不引入打包工具，脚本不用 `import` / `export`。共享名字挂在 `globalThis.OP` 上。
- 服务工作线程用 `importScripts` 载入共享文件。路径相对于 `src/background/service-worker.js`。
- 内容脚本由清单按这个顺序注入：`constants.js`、`sites/bilibili.js`、`sites/index.js`、`content/ui.js`、`content/content-script.js`。它们在隔离世界，`all_frames` 为 false，`run_at` 为 `document_start`。
- 弹出页用 `script` 标签载入 `constants.js` 和 `time.js`。弹出页和内容脚本都不调用 `chrome.storage`。要写的数据都发给服务工作线程。
- 服务工作线程用 `sender.tab.id` 识别标签页。
- 界面文字用中文。第 4 节和需求里已经写死的文案用原文。
- 目的询问、时长打断、暂时关闭面板、工具栏弹出页只用深色。颜色用设计第 6.1 节那一组。
- 扩展不把目的、备注、回答、列表或设置发到网络。
- 写入失败时不关闭询问或打断窗口，提示「没能保存，请再试一次」。「关闭当前标签页」在写入失败时不执行。
- 名称和分钟数的校验放在服务工作线程。页面上再做一遍相同校验，用来当场提示。
- 新记录、新目的、新打断选项的 id 用 `crypto.randomUUID()`。播种 id 用第 4 节的固定值。

目录以设计第 3 节为准：

```text
extension/
  manifest.json
  icons/icon128.png
  src/shared/constants.js
  src/shared/theme.css
  src/shared/storage.js
  src/shared/time.js
  src/sites/bilibili.js
  src/sites/index.js
  src/background/service-worker.js
  src/background/runtime.js
  src/content/content-script.js
  src/content/ui.js
  src/popup/popup.html
  src/popup/popup.js
  src/popup/popup.css
```

消息 `type` 以设计第 8 节为准，按下表接入。更早的任务不实现后面的处理函数。

| type | 接入任务 |
| --- | --- |
| `popup-get` | 1 |
| `content-ready`、`purpose-add`、`purpose-commit`、`purpose-skip`、`purpose-update`、`purpose-delete`、`lists-changed` | 2，其中非主页分支在任务 3 补全 |
| `settings-set`、`option-add`、`option-update`、`option-delete` | 4 |
| `interrupt-commit`、`interrupt-dismiss`、`interrupt-close-tab`、`show-interrupt` | 5 |
| `snooze-set`、`snooze-move` | 6 |

`service-worker.js` 负责启动、闹钟和标签页关闭。`runtime.js` 负责消息处理。状态以存储里的为准，内存变量只作当次处理的缓存。

## 4. 任务 1 就要定下的共享约定

后面各项沿用这些名字和形状，不再另起一套。

### 4.1 常量

`constants.js` 至少提供：

| 名字 | 值 |
| --- | --- |
| 本地键 | `localState` |
| 会话键 | `sessionState` |
| 结构版本 | `1` |
| 闹钟名 | `timer-due`、`snooze-end` |
| 名称上限 | 200 |
| 两个间隔的初始分钟 | `5` |
| 暂时关闭预设 | `10`、`30` |
| 自定义分钟框每次打开时的显示值 | `10` |
| 关掉打断窗口后再次出现 | `5000` 毫秒 |
| 拖动阈值 | `4` 像素 |
| 按钮默认边距 | 距右缘、下缘各 `24` 像素 |
| 按钮留在视口内的边距 | `8` 像素 |
| 宿主 `z-index` | `2147483646` |

消息 type 字符串与设计第 8 节相同，集中放在这一文件。

### 4.2 本地数据与会话数据

字段与设计第 4.1、4.2 节相同。`storage.js` 提供：

| 函数 | 作用 |
| --- | --- |
| `OP.createInitialLocalState()` | 返回播种后的本地状态 |
| `OP.createEmptySessionState()` | 返回空会话：`roundActive` 为 false，计时 idle，各 pending 为空 |
| `OP.ensureLocalState()` | 没有 `localState` 时写入种子。已有则原样读出，不覆盖 |
| `OP.readLocal` / `OP.writeLocal` | 读写 `chrome.storage.local` |
| `OP.readSession` / `OP.writeSession` | 读写 `chrome.storage.session` |
| `OP.normalizeName(raw)` | 去掉首尾空白。空字符串或超过 200 字则失败 |
| `OP.parseMinutes(raw)` | 只接受大于或等于 1 的整数 |
| `OP.choiceLabel(local, record)` | 按设计第 4.1 节把一条记录变成展示用的选择文案 |
| `OP.purposeContrast(local, record)` | 从一条目的记录得到名称和非空备注 |

初始目的 id 为 `purpose-seed-1` 至 `purpose-seed-7`，`order` 为 1 至 7，名称顺序是：学习、游戏攻略、追番、健身、生活经验、关注更新、其他。

初始打断选项：

| id | 名称 | order | locked | closesTab |
| --- | --- | --- | --- | --- |
| `interrupt-other` | 其他 | 1 | true | false |
| `interrupt-close-tab` | 关闭当前标签页 | 2 | true | true |

`settings.firstIntervalMinutes` 和 `settings.againIntervalMinutes` 都是 `5`。`snooze.until`、`snoozeButton.xRatio`、`snoozeButton.yRatio` 都是 `null`。`records` 是空数组。`purposeSnapshots` 是空对象。

### 4.3 时间与站点

`time.js` 提供：把分钟换成毫秒；用本机时区格式化到秒（`YYYY-MM-DD HH:mm:ss`）；格式化到时分（`HH:mm`，24 小时制）；格式化截止日期到分钟（`YYYY-MM-DD HH:mm`）。时间戳用 `Date.now()`。

`sites/bilibili.js` 提供设计第 9 节的 `id`、`matches`、`isHome`、`isPrimary`、`entry`、`pausePlayback`。`entry` 第一版为 `all`。`pausePlayback` 收集顶层文档里正在播放的 `video`，调用 `pause()`，并返回只恢复这些元素的函数。`play()` 被拒绝时忽略。

`sites/index.js` 提供 `OP.findSite(url)`。没有匹配时返回空。

主页、视频播放页、番剧播放页、搜索页、推荐页的判断条件用设计第 6.5 节。查询参数和片段不影响主页判断。

### 4.4 提示文案

需求已经规定的按钮和标题用原文。下面这些提示需求没有写死字句，实现统一用这一列：

| 场合 | 文案 |
| --- | --- |
| 名称为空 | 请输入名称 |
| 名称超过 200 字 | 名称不能超过 200 个字 |
| 分钟数不合法 | 请输入大于或等于 1 的整数 |
| 保存失败 | 没能保存，请再试一次 |
| 删除目的前的确认 | 删除这个目的？ |
| 删除自定义打断选项前的确认 | 删除这个打断选项？ |
| 打断窗口里的目的对照标题 | 这次的目的 |
| 记录来源 | 目的询问、时长打断 |
| 未生效的暂时关闭按钮 | 暂停 |
| 生效中的按钮 | 至 HH:mm |
| 弹出页的两个输入标签 | 首次打断间隔（分钟）、再次打断间隔（分钟） |

删除确认使用浏览器自己的确认框。

## 5. 任务 1：扩展骨架与播种

**目标。** 用开发者模式加载 `extension/` 后，扩展名叫「有目的」。新安装写入第 4 节的本地种子。弹出页能读到这份种子。

**本项要有的文件。** `manifest.json`、`icons/icon128.png`、`constants.js`、`theme.css`、`storage.js`、`time.js`、`sites/bilibili.js`、`sites/index.js`、`service-worker.js`、`runtime.js`、`popup.html`、`popup.js`、`popup.css`。内容脚本文件留到任务 2。

**清单。**

| 项 | 值 |
| --- | --- |
| `manifest_version` | `3` |
| `name` | 有目的 |
| `version` | `0.1.0`（只为满足清单格式） |
| `description` | 在哔哩哔哩上询问目的并到时打断 |
| `permissions` | `storage`、`alarms`、`tabs` |
| `host_permissions` | `https://*.bilibili.com/*`、`https://bilibili.com/*` |
| 背景 | `src/background/service-worker.js` |
| 弹出页 | `src/popup/popup.html` |
| 图标 | `icons/icon128.png` |

图标是 128×128 的 PNG，深色底即可。本项先不写 `content_scripts` 和 `web_accessible_resources`，避免清单指向还不存在的文件。

**行为。**

- `importScripts` 按 constants、time、storage、bilibili、index、runtime 的顺序载入。
- 服务工作线程启动时调用 `ensureLocalState()`。已有 `localState` 时不重新播种。
- 只实现 `popup-get`。回复本地状态的只读副本：目的、打断选项、两个间隔、记录。记录按设计第 4.1 节排好序，并带上展示文案。此时记录为空。
- 弹出页宽 360 像素，高不超过 560 像素。四块区域都在：间隔、目的、打断选项、记录。本项只展示，不能改。间隔显示 5 和 5。目的七项按 `order`。打断选项两项。记录区为空。样式链接 `theme.css`，深色背景、浅色文字。
- `theme.css` 写好设计第 6.1 节的颜色，供后面的 Shadow DOM 和弹出页共用。本版不写浅色变量。

**本项不做。** 内容脚本、询问窗口、闹钟、计时、暂时关闭按钮、任何写入型消息。

**验收。**

| 操作 | 应当看到 | 需求 |
| --- | --- | --- |
| 加载 `extension/` | 扩展管理页出现「有目的」，没有清单错误 | C-1 |
| 第一次加载后看弹出页 | 七个初始目的、打断选项「其他」和「关闭当前标签页」、两个间隔都是 5、记录为空。深色背景、浅色文字 | FR-5.2、FR-5.5、FR-5.6、C-6 |
| 改一项目的名称的存储值后重新加载扩展 | 弹出页仍是改过的名称，没有变回种子 | 设计第 4.1 节 |
| 删掉 `localState` 后再让服务工作线程启动 | 再次出现种子 | 设计第 4.1 节 |

存储可以在扩展服务工作线程的开发者工具里查看。

## 6. 任务 2：主页目的询问与复盘

**目标。** 打开哔哩哔哩主页时弹出目的询问。确认或跳过写入记录。弹出页能看记录，并能改名、删除目的。询问窗口里能添加目的。

**本项新增的文件。** `content/ui.js`、`content/content-script.js`。清单补上内容脚本和 `web_accessible_resources`（`src/shared/theme.css`，只对哔哩哔哩网址开放）。

**行为。**

- 内容脚本在 `document_start` 运行。还没有 `documentElement` 时等到能挂节点再挂。非 HTML 文档不挂界面。
- 界面挂在 `document.documentElement` 末尾的宿主上，使用 Shadow DOM。样式用 Shadow DOM 里的链接载入 `theme.css`。宿主 `z-index` 为 `2147483646`。每次显示询问时把宿主挪到末尾。
- 显示前先退出全屏。遮罩铺满视口并接收点击。点击遮罩不关闭窗口。页面在遮罩下不能操作。
- 注入时发送一次 `content-ready`，带上当前网址。软导航不发送。
- 本项的显示规则只处理主页：`findSite` 有结果且 `isHome` 为真时显示目的询问，并把该标签页放进 `purposePending`，把 `roundActive` 设为 true。非主页先不显示。任务 3 补全其余分支。是否显示以服务工作线程的回复为准。
- 窗口标题为「本次使用的目的是什么」。目的按 `order` 列出。列表下方可以添加目的。没有编辑、删除，也没有「跳过」以外的关闭方式。「跳过」在窗口底部。
- 选中一个目的后，在该项下方出现备注框和「确认」。没点确认不写记录。备注可以空着。点「跳过」立即写一条 `kind` 为 `skip` 的记录并关闭窗口，不出现备注框。
- 确认写入的记录：`source` 为 `purpose`，`kind` 为 `purpose`，带 `purposeId`，`note` 没写就是空字符串。`latestPurposeRecordId` 指到这条或跳过那条。该标签页移出 `purposePending`。`purposeAnswered` 在第一次确认或跳过后为 true。
- 本项不设 `timer-due`，不计时。
- 添加目的：服务工作线程校验名称，`order` 为当前最大值加 1，回复新列表。窗口立即能选中它。
- 弹出页换成设计第 7 节的布局。记录新的在前，显示到秒的时间、来源、选择或回答、非空备注。没有删除记录的控件。目的每一行可以改名或删除。删除前用「删除这个目的？」。没有添加框。
- 改名只改当前名称。删除时先把当时的名称写入 `purposeSnapshots[id]`，再从列表去掉。不改记录里的备注，也不删记录。
- 改名或删除成功后，向已打开的哔哩哔哩标签页发送 `lists-changed`。正在显示的目的列表跟着刷新。
- 用浏览器关掉还没回答的标签页时不写记录，并把它移出 `purposePending`。本项若这是最后一个哔哩哔哩标签页，将会话写成 `createEmptySessionState()`。

**本项不做。** 非主页的询问规则、闹钟、时长打断、暂时关闭按钮、间隔和打断选项的编辑。

**验收。** 在主页上对照。

| 操作 | 应当看到 | 需求 |
| --- | --- | --- |
| 关掉全部哔哩哔哩标签页后打开主页 | 深色窗口「本次使用的目的是什么」，七个初始目的和「跳过」 | AC-1 |
| 选择一个目的，填写备注后确认 | 窗口关闭。弹出页有一条来源为「目的询问」的记录，含该目的、备注和时间 | AC-2 |
| 备注留空后确认 | 记录在，弹出页没有备注行 | AC-3 |
| 点击「跳过」 | 窗口关闭。没有备注框。选择为「跳过」 | AC-4 |
| 只选中目的，不确认，打开弹出页 | 没有新记录 | AC-5 |
| 在询问窗口添加目的并用它完成询问 | 列表里立即出现。记录中的选择是该项 | AC-6 |
| 在弹出页改名后再看旧记录；删除后再看旧记录，并再次打开主页 | 改名后旧记录显示新名称。删除后旧记录仍是删除前的名称。询问里不再有该项 | AC-7 |
| 询问出现后点页面，再刷新主页 | 页面被挡住。刷新后再次挡住并询问。刷新前没有新记录 | AC-32 |
| 产生目的和跳过记录后重启浏览器，打开弹出页 | 记录仍在，新的在前。没有删除单条记录的操作 | AC-26 |
| 看询问窗口和弹出页 | 深色背景、浅色文字。没有主题切换 | AC-42 的这两处 |

## 7. 任务 3：目的询问的触发范围

**目标。** 把设计第 6.2 节的显示表做全。任务 2 已经会在主页询问。本项补上新一轮、未完成时刷新，以及回答之后不再问非主页。

**行为。** `content-ready` 按下表决定。主页的一行任务 2 已经有了，保持不变。

| 情况 | 是否显示 |
| --- | --- |
| 主页发生一次新的文档加载 | 显示 |
| 非主页加载时 `roundActive` 为 false | 显示，并设为 true |
| 非主页加载时该标签页仍在 `purposePending` | 显示 |
| 非主页加载时这一轮已经开始，且该页不在 `purposePending` | 不显示 |
| 地址变了但文档没有重新加载 | 不重新判断。已经打开的询问留在当前文档上 |

另外：

## 9. 任务 5：共用计时与时长打断

**目标。** 所有哔哩哔哩标签页共用一个按实际时间走动的计时。到点后每个标签页都弹出「现在在做什么」。回答、关掉窗口、关闭当前标签页的规则按需求 FR-2。

这一项最大。按下面的顺序写，写完再一起验收。

1. 会话里的计时字段、`timer-due` 闹钟、标签页关闭时清轮次。
2. 到点后给每个哔哩哔哩标签页发 `show-interrupt`，并画打断窗口。
3. 暂停和恢复播放、关掉后 5 秒再弹、关闭当前标签页。
4. 多标签页各自记录、全部完成后再用再次打断间隔。
5. 目的询问未完成时不计时；同一页两窗口都要出现时先显示目的询问。
6. 修改「当前正在使用的那种间隔」时按设计第 5.2 节重算。

**计时。**

- 到期时刻是 `startedAt + 间隔分钟 × 60 × 1000`。闹钟 `timer-due` 的 `when` 设在该时刻。进入不走动的状态时清除这个闹钟。
- 目的询问被确认或跳过，并且 `purposePending` 已空，也没有待显示的时长打断：从现在起用首次打断间隔。
- 还有别的页面挂着目的询问：先不启动。最后一次使 `purposePending` 变空时再启动。
- 确认或跳过时该页还要接着显示时长打断：不启动计时，先显示打断。
- 某个标签页进入 `purposePending` 时，若计时正在走，丢掉这一段 `startedAt` 并清除闹钟。询问期间流过的时间不在确认后补上。
- 一轮打断的 `pending` 变空，并且仍有哔哩哔哩标签页：从现在起用再次打断间隔。已经没有哔哩哔哩标签页：会话写成空状态，不启动间隔。
- 打断进行中不启动下一次间隔。关掉窗口后的 5 秒也不启动。
- 只关闭一部分标签页，或刷新，不清零。
- 最后一个哔哩哔哩标签页关闭、退出浏览器、重新加载扩展：进行中的计时清零。退出浏览器和重新加载扩展时会话由 Chrome 清掉。
- 服务工作线程启动时，若会话里没有正在走动的计时，清除残留的 `timer-due`。浏览器退出后闹钟可能还在，不得因此弹出时长打断。
- 页面在后台、视频暂停、电脑休眠期间，计时继续。不用页面里的 `setTimeout` 担任共用计时，也不用 `performance.now()`。
- 修改间隔时，若计时正在走，且改的是 `timer.intervalKind` 那一种：保留 `startedAt`，用新分钟数重算 `timer-due`。若新的到期时刻已经不晚于现在，立即进入一轮打断。另一种间隔只写入设置。计时没在走时，两个数字都只更新设置。

**一轮打断。**

- 间隔到期且当时有哔哩哔哩标签页：计时改为不走动，`interrupt.active` 为 true，`interrupt.reason` 为 `timer`，`pending` 放上当前每一个哔哩哔哩标签页 id，并向这些页发送 `show-interrupt`。
- 这一轮结束前新打开的哔哩哔哩标签页也加入 `pending` 并显示打断。
- 窗口标题为「现在在做什么」。能解析到 `latestPurposeRecordId` 时，在选项上方显示「这次的目的」、名称，以及非空备注。没有记录则不显示这块。
- 选项来自 `interruptOptions`，按 `order`。选中 `closesTab` 为 false 的项后出现备注框和「确认」。确认后只写当前标签页的一条记录，并只关闭该页窗口。`kind` 为 `option`，`optionName` 是写入当时的名称。
- 「关闭当前标签页」不出现备注框，也不再要一次确认。先写 `kind` 为 `close-tab` 的记录，成功后再 `chrome.tabs.remove`。失败则标签页保持打开，窗口留着并提示保存失败。
- 用浏览器自身控件关掉标签页时，不写「关闭当前标签页」记录，只把该页移出 `pending` 和 `purposePending`。
- 窗口右上角的「关掉」发送 `interrupt-dismiss`：不写记录，不移出 `pending`。若关闭前视频正在播放，并且是被这次窗口暂停的，则恢复播放。内容脚本用 `setTimeout` 在 5 秒后再次显示并再次暂停。这 5 秒不用闹钟。
- 这 5 秒内若发生整页加载，新的内容脚本看到该页仍在 `pending`，立即显示，不等剩余的 5 秒。
- 同一标签页上目的询问还在时，内容脚本先记住打断，等目的询问结束再画。
- 出现窗口时用站点模块暂停播放。先退出全屏再显示。

**本项不做。** 暂时关闭按钮、`snooze-end`、第二个网站。

## 10. 任务 6：暂时关闭

## 11. 任务 7：站点边界
