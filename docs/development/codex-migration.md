## hooks 审核边界

原 `extension_guard.py` 依赖 Cursor 工具的 `path/file_path`、`contents/new_string` 等输入，不能直接假定兼容 Codex 的补丁工具或 shell 写入。其文本扫描还存在以下限制，因此没有原样移植成强制拦截器：

- `strip_js` 会整体移除模板字符串，遗漏 `${...}` 中可执行表达式；正则字面量等也可能误命中。
- 无效 manifest JSON 返回空违规列表，缺少必需字段时也可能放过；没有完整检查 `run_at`、隔离世界、资源与权限。
- theme 检查只判断六种颜色是否出现，不能证明实际 UI 使用正确；写入预检不会执行该检查。
- 异常处理会返回 allow 或空结果；读取“允许”不能证明文件符合约束。
- service worker 定时器扫描会拒绝所有 `setTimeout`，比“不用定时器担任共用计时”的原要求更宽。

后续若要强制执行，应针对实际运行环境的 hook 协议另行集成并验证拦截行为；本次交付是可发现的项目指令、技能和明确的验证流程。
